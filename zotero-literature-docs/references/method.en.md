# Generating Word / PDF Literature Documents from Zotero (Full Method)

## Core principles

1. **Data must come from the Zotero local API (JSON)**, never from `export-bibtex` text. BibTeX exports garble special characters (en dashes, curly quotes, ligatures such as ﬃ), producing mojibake like "鈥恊diting" or "铿乧iency".
2. Word is generated with python-docx; PDF is generated with fpdf2. Both share `work/data.json`.
3. After generation, every output must be scanned to confirm there is no garbled text (see Validation below).

## Steps

1. Confirm the Zotero local API is running:
   `python3 <zotero-skill>/scripts/zotero.py status --json`
2. Fetch clean data (comma-separated item keys):
   `python work/fetch_items.py --keys KEY1,KEY2,...` → writes `work/data.json`
3. One-command generation + validation (Word + PDF + garble scan):
   `python work/run_all.py [doc_config_xxx.json]`
   Each topic has one config file (title + sections + item keys); the default config is used when no argument is given.
4. Output files land in `outputs/`: e.g. `基因遗传转化文献.docx`, `基因遗传转化文献.pdf`.
5. To repair garbled fields in BibTeX files: `python work/fix_bib.py`.
6. Review documents: content is written in `work/review_content.json`; in-text citations use `[@ZoteroKey]` (auto-numbered). Run `python work/make_review_docs.py` to generate the review Word + PDF, which automatically appends the reference list in citation order.
7. PPT: `python work/assemble_pptx.py` (internally calls `build_pptx.py` to generate slide content, then merges it into the PowerPoint-generated `work/_skeleton.pptx` skeleton so the package stays valid). Figures are produced with `work/extract_figures.py` from the paper PDFs; slides label them "图片引自参考文献 [n]" ("Figure from reference [n]").

## PPT pitfalls (2026-08-04)

- Hand-written pptx skeletons (theme/master/layout) are rejected by PowerPoint; always use a PowerPoint-generated blank template as the skeleton and replace the slide XML.
- Text centering must be `algn="ctr"`; `algn="c"` is judged as corrupted.
- When adding PNG media, add `<Default Extension="png" .../>` to `[Content_Types].xml`.
- Preserve each slide's original `.rels` bytes and only append image relationships; do not rewrite the whole block.
- PowerPoint COM automation that opens PPTs containing images must use `WithWindow=$true`; windowless mode falsely reports "cannot open the file". COM `AddPicture` is unstable on this machine and can hang — do not rely on it.

## Dependencies (installed under `work/`, no re-download needed)

- `work/pylibs`: fpdf2 + fontTools (PDF generation)
- `work/pylibs2`: python-docx + lxml (cp314, not cp314t) + typing_extensions (Word generation)
- To reinstall: download the wheels from PyPI and unpack them into the corresponding directories; lxml must be `cp314-cp314-win_amd64` (not cp314t); fpdf2 needs fontTools.

## Pitfalls (to avoid next time)

- PDF font: use DengXian `Deng.ttf` / bold `Dengb.ttf`; do not use SimHei (fpdf2 `multi_cell` reports "Not enough horizontal space").
- After every `multi_cell`, fpdf2 leaves x at the right margin; call `set_x(l_margin)` before the next cell.
- Word Chinese fonts must set `rPr/rFonts` `eastAsia` explicitly (Microsoft YaHei).
- Scripts containing Chinese filenames must be written as `.py` files before running (inline PowerShell heredocs corrupt Chinese via GBK).
- When checking the output directory, glob matches Word lock files starting with `~$` (not zip files, falsely flagged as corrupted); exclude or clean them first.
- Word COM automation on this machine (Documents.Open/SaveAs2) is unstable and can hang; do not rely on it for document conversion.

## Update (2026-08-05): usability improvements

Based on a full run (anthocyanin review + MBW topic + two decks), the following improvements were made:

1. **Unified CLI**: new `scripts/zotero_docs.py` with `setup / status / search / fetch / texts / review / figs / ppt` subcommands; run from the project root. The first run automatically copies the pipeline scripts and skeleton into `work/`.
2. **Cropped real figures**: `extract_figures.py` now crops embedded raster figures by their bounding boxes (`<KEY>_f1.png`) instead of whole-page screenshots; `--whole-page` remains as an explicit opt-in mode. Keys are passed via CLI or `--keys-file`, no longer hard-coded.
3. **JSON-driven PPT content**: new `scripts/deck_config.example.json`; slide content lives in `work/deck_config.json` (cover/toc/pic/text/refs slide types) with no need to edit Python code.
4. **No 16-slide limit**: `assemble_pptx.py` supports any slide count — clones slide parts when there are more slides than the skeleton, and drops unused parts when there are fewer, keeping Content_Types/relationships consistent.
5. **Robust data fetch**: `fetch_items.py` skips and warns on stale/404 keys (no more KeyError crash) and cleans leading numbering noise in titles (e.g. "1 Elucidation of …").
6. **Citation integrity check**: `make_review_docs.py` verifies before generation that every `[@KEY]` exists in `data.json` (errors and lists missing ones), and warns about uncited items.
7. **Reading support**: new `extract_texts.py` extracts the first two pages and the last page of each PDF into `work/paper_texts/`, for reading abstract / intro / conclusion before writing the review.

Non-negotiable rules that still apply: data must come from the Zotero local API JSON; Word Chinese uses `eastAsia=Microsoft YaHei`; PDF uses Deng fonts with `set_x` after every `multi_cell`; PPT is merged into a PowerPoint-generated skeleton; PPTs containing images must be opened with a visible window for validation.

## Update (2026-08-05, 2nd): PDF layout and data robustness

1. **PDF layout rework**: review PDFs use a new layout — centered title with a decorative rule, indented intro, section headings with a left color bar and thin separator, hanging-indent entries, two-character first-line indents, left-aligned body text (avoiding the intra-line gaps of justified text), numbered hanging references, and a footer with a thin line and "第 n 页 / 共 N 页". Line spacing, margins and whitespace were adjusted accordingly.
2. **Fetch in batches of 25 keys**: the Zotero local API silently drops items for very long itemKey lists (1 item was lost with 50 keys), so requests are now small batches.

## Update (2026-08-05, 3rd): review documents restyled to Chinese journal format

1. **Typography**: PDF body SimSun (宋体) 10.5 pt, line spacing ≈ 5.6 mm; Chinese title SimHei (黑体) 22 pt; level-1 headings SimSun 14 pt (numbered 1, 2, …); level-2 headings SimHei 10.5 pt (numbered 1.1, 1.2, …); abstract/keywords SimHei 9 pt; references SimSun 7.5 pt. No running header; footer only the page number. Body paragraphs: two-character first-line indent, left-aligned.
2. **Citation format**: in-text citations switched to author-year, e.g. （Zhang et al.，2015）、（Porra & Grimme，1978）; the reference list is sorted alphabetically by first author's surname in the format "作者. 年份. 标题. 期刊，卷(期)：页码. DOI：…", consistent with Chinese journal style.
3. **Tables and figures**: content JSON groups may carry `table` (caption/caption_en, columns, rows, widths) or `image` (path, width, caption/caption_en). In the PDF, table captions go above the table and figure captions below, both bilingual (Chinese + English); tables have grid lines, bold SimHei headers and SimSun 7.5 pt body. Word renders tables and images the same way.
4. Font dependencies: `C:\Windows\Fonts\simsun.ttc` (SimSun) and `simhei.ttf` (SimHei), with automatic fallback to Deng/DengB when missing.

## Update (2026-08-05, 4th): final consolidation (per user feedback)

The following rules are now written into `make_review_docs.py` and the other scripts and apply by default to new tasks:

1. **Citation format**: author-year in-text citations （Zhang et al.，2015）; consecutive citations merge into one parenthesis separated by semicolons; entries without authors display as "佚名，年份". References sorted alphabetically by first author, format "作者. 年份. 标题. 期刊，卷(期)：页码. DOI：…"; the last author is abbreviated with a dot before the year; continuation lines use a hanging indent of two characters. English titles use sentence case (lowercase in the middle); gene names keep capitals and are italic; Latin binomial genus names are italic with a capital initial; author names are regular with capital initials.
2. **PDF layout (Chinese journal style)**: SimSun body 10.5 pt, SimHei title 22 pt, level-1 headings SimSun 14 pt, level-2 headings SimHei 10.5 pt, abstract/keywords SimHei 9 pt, references SimSun 7.5 pt; two-character first-line indents, flush-left continuation lines; titles wrap greedily by character width (the trailing character is centered on the second line to avoid a lone short word); content bottom bound 272 mm to prevent blank single-line pages; tables prefer to stay on one page, may span two pages with the header repeated; three-line tables; the abstract label and text stay on the same line.
3. **Word layout**: Chinese font SimSun, English Times New Roman; SimHei (headings/table headers/captions) without bold; footer "第 X 页 / 共 Y 页"; titles follow the same wrapping rules as the PDF; table rows cantSplit and keepNext except the last row, matching the PDF pagination behavior.
4. **Italics rules**: gene names (BBM, LEC1, AP1, LFY, etc.) and plant Latin binomials are italic; protein/enzyme abbreviations ("蛋白/酶 XX" / "XX 蛋白/酶" contexts) are regular; a genus whitelist plus common-word filters avoid false italics (e.g. "Current progress", "Genes and" are not italicized); the rule sets can be extended per topic. Word implements run-level italics; PDF renders italic Latin fragments with Times Italic and Chinese/regular fragments with SimSun.
5. **Missing glyphs in PDF**: Latin extended characters missing from SimSun (e.g. ę) are normalized via `pdf_safe` (diacritics removed); Chinese punctuation is unaffected.
6. **Citations in table cells**: `[@KEY]` inside PDF/Word table cells is automatically rendered as author-year citations, supporting a "references" column.
7. **Robustness**: all scripts reconfigure stdout/stderr to UTF-8 to avoid crashes printing special characters on a GBK console; fetch batches 25 keys per request; stale items are skipped with warnings; numbering noise in titles is cleaned automatically.
8. **PPT**: slide content is driven by `deck_config.json` (cover/toc/pic/text/refs), any slide count; figures are cropped real figures by default (`--whole-page` is the explicit full-page mode); `build_pptx` citation counting is compatible with section groups that contain only tables and no items.

## Update (2026-08-05, 5th): Latin italics and title rules finalized

1. **PDF Latin italics**: the PDF renders italic fragments (gene names, Latin binomials) with Times Italic (timesi.ttf) and Chinese/regular fragments with SimSun; Word implements run-level italics. Both share the same `italic_spans` rules, so Word and PDF stay consistent (the English abstract also applies the italics rules).
2. **Reference titles**: English titles use sentence case (lowercase in the middle); fully capitalized abbreviations/gene names keep capitals; full gene names (e.g. AUXIN RESPONSE FACTOR) are capitalized and italic; binomial genus and species names are italic, while naming authorities (e.g. Linden., Pierre ex A. Froehner) keep a capital initial and regular type; author names are regular with capital initials.
